# Dominant — CRM стоматологической клиники

Полноценное веб-приложение (+ PWA, + Windows-десктоп) для управления клиникой
Dominant: календарь записей, карта пациента с одонтограммой, счета и оплаты,
касса и финансовая аналитика. Три роли с разным доступом — администратор,
врач, ресепшн — всё разграничение проверяется на сервере, не только в интерфейсе.

## Как это устроено

```
dominant-app/
├── server/     Express + Socket.io + node:sqlite (весь бэкенд и API)
├── web/        Статический фронтенд (одна SPA), он же PWA
├── electron/   Windows-десктоп — тонкий клиент, открывает адрес сервера
├── Dockerfile  Сборка сервера для Railway
└── railway.json
```

Архитектура: **один сервер** на Railway хранит все данные клиники (SQLite-файл
на постоянном диске). Все, кто заходит в CRM — из браузера, с телефона
(установив PWA) или через Windows-приложение — просто подключаются к этому
серверу по сети. Ничего не хранится по отдельности на компьютере каждого врача.

## Установка и первый запуск (Railway)

1. Зайдите на [railway.app](https://railway.app) и войдите (можно через GitHub).
2. **New Project → Deploy from GitHub repo** → выберите этот репозиторий.
   Railway увидит `railway.json` и соберёт проект по `Dockerfile` автоматически.
3. Добавьте постоянный диск, чтобы данные клиники не терялись при передеплое:
   на холсте проекта (не во вкладках Settings сервиса — там его может не быть)
   нажмите **+ New** / **+ Add** → **Volume**, подключите его к сервису
   `dominant_clinic_crm` и укажите путь монтирования `/data`.
4. В **Variables** добавьте:
   ```
   DATABASE_PATH=/data/dominant.db
   JWT_SECRET=<любая длинная случайная строка>
   ```
   (`JWT_SECRET` можно сгенерировать, например, командой `openssl rand -hex 32`.)
5. Дождитесь деплоя — во вкладке **Settings → Networking** нажмите
   **Generate Domain**, чтобы получить публичный адрес вида
   `dominant-crm-production.up.railway.app`.
6. Откройте этот адрес в браузере — сервер сам засеет демо-данные клиники при
   первом запуске (см. тестовые PIN-коды ниже). Дальше можно удалять демо-записи
   и вносить реальные через интерфейс.

После этого **любое** обновление, запушенное в `main` (или в ветку, которую
Railway отслеживает), передеплоится автоматически — отдельно ничего включать
не нужно.

## PWA (уже работает)

Открытый в браузере адрес клиники — это уже полноценное PWA: на телефоне
браузер предложит «Установить приложение» / «Добавить на экран Домой», на
компьютере — значок установки в адресной строке Chrome/Edge. Офлайн работает
только оболочка интерфейса (без выхода в сеть данные всё равно не получить —
это база клиники, не локальный кэш).

## Windows-приложение (.exe)

`electron/` — не отдельная копия CRM, а окно, которое открывает адрес вашего
сервера на Railway. Собирается через GitHub Actions прямо в этом репозитории:

1. Вкладка **Actions** → **Build Windows App** → **Run workflow** (кнопка
   справа) — через пару минут в этом запуске появятся файлы во вкладке
   **Artifacts**: обычный установщик и портативная версия.
2. Либо создайте тег версии — тогда дополнительно появится публичный **Release**
   со скачиваемыми файлами:
   ```
   git tag v1.0.0
   git push --tags
   ```
3. При первом запуске приложение спросит адрес сервера клиники — вставьте туда
   адрес из Railway (шаг 5 выше). Дальше он запоминается, спрашивать не будет
   (сменить его потом можно через меню «Dominant CRM → Сменить адрес сервера…»).

## Локальный запуск для разработки

```bash
cd server
npm install
npm run seed      # один раз — наполняет базу демо-данными
npm run dev        # сервер на http://localhost:4000, там же отдаётся web/
```

`web/` ничего собирать не нужно — сервер раздаёт его как статику. Открывайте
`http://localhost:4000`.

## Роли и доступ (проверяется на сервере)

- **Админ** — видит всё: общий календарь всех врачей, всех пациентов, все
  счета, кассу и расходы, настройки клиники и прайс-лист.
- **Ресепшн** — календарь, пациенты, счета (без финансовой аналитики и кассы).
- **Врач** — только свой календарь, только своих пациентов (по записям или как
  лечащий врач) и только свои счета. Сервер сам отфильтровывает данные при
  каждом запросе — это не скрытие в интерфейсе, а реальное ограничение доступа.

## Технологии

Node.js + Express + Socket.io (realtime-обновления между открытыми вкладками
без перезагрузки) + `node:sqlite` (встроенный в Node модуль — без нативных
бинарников, поэтому деплой одинаково надёжен на любой платформе) + JWT-аутентификация
+ bcrypt для PIN-кодов. Фронтенд — самостоятельный SPA без сборщика, в стиле
вывески клиники (чёрный/белый + бронза).
